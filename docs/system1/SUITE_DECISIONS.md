# OpenFARM — repair-or-retire decisions

**Date:** 2026-10-15 · **Branch:** `research/system1-reboot-2026-10`  
**Policy:** No old task enters the executable System-1 suite simply because a dataset exists. Either **repair and radically narrow the question to what is grounded**, or **retire it**. Historical raw data, notebooks and Git commits remain available for provenance, but retired tasks have **no active evaluation/training configuration** and their environment loaders reject calls. We are not deleting third-party HF datasets.

**Three retained research tasks are NOT clinically, commercially, or calibration certified.** They are bounded training/evaluation candidates. Each would require independent scientific-label verification, proper probabilities/calibration experiments, rights clearance, and deployment-distribution measurements before being called product ready. "Retained" is an explicit scope restriction, not evidence of strong model quality.

## What is actually active

- **`openfarm-horse-grimace`**: only `region_score` (ordinal, 0/1/2), HF revision `ba5799d2c29886e238f8a069fb3501d1d91444f5`; `binary_pain` rejected.
- **`openfarm-bioacustics`**: only `catmeows_context` (revision `57fe220b22eae46eb555af9f4169bd4677584cea`) and **provisional** `soundwel_call_type` (revision `4164e39798c2e65bce5ef8d56159d98e1267f577`). Six other registry tasks are removed. Both require recording/spectrogram input, pin checked versions, and exclude metadata-only decisions.
- **`openfarm-aww`**, **`openfarm-dog-pain-triage`**, **`openfarm-sheep-apr`**, **`openfarm-zoo-arousal-eval`**: retained in Git **as historical implementations only**; their loader immediately raises a retirement error. Their active TOML eval/old RL configs are removed.

The active-environment smoke check verifies runtime refusal, not only documentation. Retired definitions can be retrieved from Git history for historical reproduction; they **cannot** be reinstated merely through legacy `allow_uncertified` flags.

**Important semantic gate:** Existing legacy environments output exact XML answers (generative evals). Even retained tasks are **not yet TypeSafe/JEV probabilistic, calibrated decision-model benchmarks**. Before using them to claim System-1 success, create exact question/option/rubric schemas, retain full probabilities, evaluate Brier/log loss and calibration against held-out examples, and report latency/cost and generalization uncertainty.

## Decision revision policy

A retired dataset can return only under a **new independently audited dataset version** with a concrete fix, immutable source manifest, sample-level evidence, source rights, full duplicate/group tests and new task contract. Do **not** delete historical failed evidence or mark an old task as repaired without a fresh test. A source may still be useful for **different** tasks after new labels are obtained, but inventing a new question with old label columns does not create new supervision.
